    Reference¶

    Tips and Common Pitfalls¶

    • Run from the root directory

      Always execute from the main directory so that the proper modules are used.

    • Respect the sequence

      Every step depends on the outputs of the one before it.

    • Review judgment

      simulate_forecast is where judgment is applied — revisit existing adjustments against current conditions.

    • Use the report steps

      Steps 4, 6 and 8 validate calibration, data quality and forecast reasonableness.

    Quick troubleshooting¶

    Symptom Likely cause What to do
    ModuleNotFoundError or wrong module runs Command run outside the project root, or cpm_venv not active cd to the project root and activate cpm_venv
    Packages fail to install Environment not activated before pip install Activate first; prompt should show (cpm_venv)
    bt.request_data fails External or India forecast not yet submitted, or IDs do not match Complete us → cn/jp/ea → in; check IDs in attributes.json
    Tunes not applied annual_tunes.csv still open or forecast_span not set to 1 Save and close the file; check forecast_span = 1
    Implausible growth or rates Rates entered as percentages Enter decimals; roc is gross (5% → 1.05)

    Command Cheat Sheet¶

    Environment¶

    python -m venv cpm_venv
cpm_venv\Scripts\activate
pip install -r requirements.txt

    python3 -m venv cpm_venv
source cpm_venv/bin/activate
pip install -r requirements.txt

    Data¶

    python -m datastore_pumps.update_all

    Country models¶

    `python -m {country}.{step}`
    # Step Command (Bhutan)
    1 Create Model python -m ph.create_model
    2 Request Data python -m ph.request_data
    3 Prepare History python -m ph.prepare_history
    4 Review Steady-State python -m ph.report_steady_calibration
    5 Filter History python -m ph.filter_history
    6 Report Filter python -m ph.report_filter
    7 Simulate Forecast python -m ph.simulate_forecast
    8 Report Forecast python -m ph.report_forecast
    9 Submit Forecast python -m ph.submit_forecast
    — All steps (skips 4 and 6) python -m ph.run_all

    Run order¶

    datastore_pumps → us → cn · jp · ea → in → bt

    Key files¶

    File Purpose
    datastore/data.csv Central datastore output
    {country}/attributes.json Forecast IDs and sample periods
    tune_files/annual_tunes.csv Annual tunes for judgment

    Glossary¶

    Term Meaning
    CPM Country Projection Model
    Datastore Central store of historical series and submitted forecasts, served through datastore_api
    External environment The US, euro area, Japan and PRC models whose forecasts feed the focus economies
    Focus economy A country forecast using the external environment (pilot: Bhutan, India, Philippines)
    Forecast ID Identifier for a forecast round; part of the datastore storage key
    Steady-state calibration The model's long-term equilibrium assumptions, reviewed in Step 4
    Kalman filter / filtering Separates trends from cyclical components in historical data (Step 5)
    Tune A target value set directly for a variable; the simulation solves for the shocks needed to hit it
    Exogenize / endogenize Fix a variable at a set value / let a shock adjust freely so the target is met
    roc Gross rate of change (e.g. 1.05 = 5% growth)
    Real exchange rate gap Computed against the US dollar using US CPI projections — the reason the US runs first

    Country codes: bt Bhutan · cn PRC · ea euro area · in India · jp Japan · ph Philippines · us United States

    Recap: From Data to Submitted Forecast¶

    1. Set up the environment and run everything from the project root.
    2. Update and refresh the datastore with datastore_pumps.update_all.
    3. Build the external environment: US first, then CN, JP and EA.
    4. Run focus countries: PH, IN, and then BT.
    5. Work through the nine steps in order, pausing at the review gates.
    6. Apply judgment through annual tunes, then report and submit.
